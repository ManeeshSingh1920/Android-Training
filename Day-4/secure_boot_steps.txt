✅ Step 4- Android Verified Boot (AVB)

Generating AVB BOOT

1. Overview

In Android 10, the kernel image and recovery image are signed using AVB (Android Verified Boot).
To enforce secure boot on Telechips SoCs:

AVB verifies kernel images

Telechips Secure Boot verifies other images

This README covers:

Generating a new RSA4096 private key

Extracting the AVB public key

Converting the public key into a C array

Replacing the key inside U-Boot (avb_verify.c)

Updating BoardConfig.mk to use the new key

2. Generate a New AVB Private Key

Navigate to your SecureBoot tool directory:
cd ~/Documents/Telchip_8050/mydroid/maincore/security_tools_v1.27/security_tools/module/SecureBoot

Create a directory to store your new private key:

# mkdir Generated_AVB_Key

Generate a 4096-bit RSA private key:
# openssl genrsa -out ./Generated_AVB_Key/rsa4096_prikey.pem 4096

You should see:

Generating RSA private key, 4096 bit long modulus (2 primes)
++++
++++
e is 65537 (0x010001)

3. Extract the Public Key for AVB

Create an output directory: 	 	 		

# mkdir Extracted_AVB_Key

Run avbtool to extract the AVB root public key:
avbtool extract_public_key \
  --key Generated_AVB_Key/rsa4096_prikey.pem \
  --output Extracted_AVB_Key/avb_root_pub.bin


Confirm the file was generated:

# ls Extracted_AVB_Key/


4. Convert Public Key to C Array
Run xxd to get a C-compatible array:

# xxd -c 10 -i -a Extracted_AVB_Key/avb_root_pub.bin


You will get an output similar to:

unsigned char Extracted_AVB_Key_avb_root_pub_bin[] = {
  0x00, 0x00, 0x10, 0x00, 0xdc, 0xc8, 0xf6, 0xed, 0xd2, 0x42,
  ...
  0x90,
};


Copy the entire array.

5. Insert Public Key into U-Boot

Edit:
$ANDROID_BUILD_TOP/bootable/bootloader/u-boot/common/avb_verify.c

Replace the existing key:

const unsigned char avb_root_pub[1032] = {
    // paste your generated array here
};

Make sure:

The array name is avb_root_pub

The size matches the length of your generated avb_root_pub.bin (typically 1032 bytes

6. Update BoardConfig.mk

Edit
$ANDROID_BUILD_TOP/device/telechips/<TARGET_PLATFORM>/BoardConfig.mk

Add or update:

BOARD_AVB_ALGORITHM := SHA256_RSA4096
BOARD_AVB_KEY_PATH := /home/oem/Documents/Telchip_8050/mydroid/maincore/security_tools_v1.27/security_tools/module/SecureBoot/Generated_AVB_Key/rsa4096_prikey.pem

Use an absolute path, not a relative one.

7. Notes

Losing your private key means you can never sign compatible updates again → keep it safe.

AVB only secures the kernel image; Telechips Secure Boot handles the rest.

The public key size must match the expected length (typically 1032 bytes).

Always rebuild U-Boot after changing avb_root_pub.

✅ Note=> # ⭐ **Summary: Secure Boot Limitations on TCC8050 (Telechips)**



Below is the **precise technical summary** of the Secure Boot restrictions on the Telechips TCC8050 platform, especially relevant while working on Android 10.

---

## 🔒 **Irreversible Nature of Secure Boot**

Once Secure Boot is enabled on a TCC8050 board:

### ❌ **You cannot disable Secure Boot again.**

Secure Boot becomes **permanently active**.

### ❌ **OTP (One-Time Programmable) memory cannot be rewritten.**

The Root Key burned into OTP is **permanent**.

---

## 🚫 **Firmware Restrictions After Secure Boot**

After Secure Boot is enabled:

### ❌ **You cannot flash normal/unsigned firmware images.**

Unsigned or modified BL1, BL2, U-Boot, OPTEE, kernel, or R5 images **will fail to boot**.

### ❌ **Fastboot flashing is no longer allowed.**

Only signed images through **FWDN** are accepted.

### ❌ **If signed images are incorrect → board will NOT boot.**

Any mismatch in signing keys, MCERT, RBID, or image formatting results in **irrecoverable boot failure**.

---

## 🔧 **Allowed Operations After Secure Boot**

Even after enabling Secure Boot:

### ✔ You *can* flash firmware

…but only:

* Using **FWDN**
* With all images **properly signed** with the correct master/image keys

Unsigned images will always be rejected by hardware verification.

---

## ⚠️ **Risk Level for Development Boards (EVB)**

Enabling Secure Boot on an EVB is **high risk**, because:

* The board becomes locked
* OTP is burned forever
* Any image signing error can **brick the EVB**
* Recovery requires **Telechips factory tools + JTAG**

It is not reversible or recoverable by developers.

---

# ⭐ **Final Recommendation**

Secure Boot should be enabled **only when the Android system is completely stable** and all partitions, bootloader components, and firmware images are finalized.

For development and debugging, Secure Boot should remain **disabled**.
